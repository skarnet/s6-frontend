The s6 configuration files

Goal and usage

/etc/s6.conf and /etc/s6-user.conf are configuration files provided by the distribution, or written by the system administrator, defining settings for the s6 commands and the path policies for system and user services respectively. Their paths can be changed at build time with --conffile and --user-conffile.

For instance, this is what allows the s6 process restart foobar command to send s6-svc -r to the foobar service without the user needing to type, or even remember, what the full path to the foobar service directory is.

Description

Both files follow the envfile syntax: simple key = value lines, comments permitted. Without -u, s6 loads the system file. With -u, it loads the user file instead. The S6_CONF environment variable overrides the selected filename.

If a value is left empty, the compiled-in or XDG-derived default for the selected profile is used. Command-line options override values from the selected file.

User profile defaults

In user mode, the default paths are:

scandir
$XDG_RUNTIME_DIR/service
livedir
$XDG_RUNTIME_DIR/s6-rc
repodir
$XDG_STATE_HOME/s6-rc/repository
bootdb
$XDG_STATE_HOME/s6-rc/compiled/current
stmpdir
$XDG_RUNTIME_DIR/s6-frontend
personal store
$XDG_CONFIG_HOME/s6/sources

XDG_CONFIG_HOME defaults to $HOME/.config and XDG_STATE_HOME defaults to $HOME/.local/state. Relative XDG paths are ignored in favour of these defaults. XDG_RUNTIME_DIR has no fallback and must be set to an absolute path.

Distributions can change the relative layout below the XDG roots at build time with --with-user-source-subdir, --with-user-repo-subdir, and --with-user-bootdb-subdir. Each value must begin with / and is appended to its corresponding XDG base directory.

The variables that can be set are the following:

scandir
The directory where s6-svscan is running. The default is /run/service (possibly overridden by the --scandir build-time configure option to s6-linux-init or to s6-frontend).
livedir
The directory hosting the live service database managed by s6-rc. The default is /run/s6-rc (possibly overridden by the --livedir build-time configure option to s6-rc or to s6-frontend).
repodir
The directory hosting the repository of service sets managed by the s6-rc repo commands. The default is /var/lib/s6-rc/repository (possibly overridden by the --repodir build-time configure option to s6-rc or to s6-frontend).
bootdb
The path to the boot-time compiled service database. The default is /etc/s6-rc/compiled/current (possibly overridden by the --bootdb build-time configure option to s6-rc or to s6-frontend).
stmpdir
A directory suitable for root-only runtime data and temporary files for s6-frontend. The default is /run/s6-frontend (possibly overridden by the --stmpdir build-time configure option to s6-frontend).
storelist
A colon-separated (:) list of directories containing the stores of s6-rc service definition directories. The system default is /usr/share/s6/sources:/etc/s6/sources (possibly overridden by the --with-store-list build-time configure option). In the machine-wide user configuration, this value is the shared package and administrator store prefix; s6 appends the personal XDG store. The shared default is /usr/share/s6/user/sources:/etc/s6/user/sources, possibly overridden by --with-user-store-list. An explicit command-line --storelist is a complete replacement and does not append the personal store.
verbosity
The default verbosity for s6 and its invoked commands. 0 is terse (only print fatal error messages), 1 is normal (print error messages and warnings), over 1 is increasingly verbose (print informational messages, up to tracing and debug messages at level 4-5). The default is 1.
fdhuser
The system user for the internal fd-holding process spawned by s6-rc. It must be a user defined in /etc/passwd. The system default is root and that is fine, but distributions may want to set it to an unprivileged user. The user-profile default is empty, so the fdholder runs as the invoking user.
